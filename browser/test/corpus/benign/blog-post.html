How we cut our build times in half

Sam Okafor · September 30, 2026 · 7 min read

Our monorepo had grown to 400 packages, and a clean CI build took 31 minutes. Here is what we changed.

1. Cache by content, not by branch

We switched the cache key from the branch name to a hash of each package's inputs.1 Cache hits went from 38% to 81%.

cache-key: ${{ hashFiles('packages/*/src/**', 'package-lock.json') }}

2. Stop building what nobody imports

A dependency graph check removed 61 dead packages. Deleting code is the fastest build.

3. Split the test run

Tests now run on eight shards balanced by last week's timings.

Footnotes

  1. Inputs include source files, the lockfile and the toolchain version. ↩
