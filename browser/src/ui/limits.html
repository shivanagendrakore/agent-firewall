What LaunchSafe does not stop

LaunchSafe holds sensitive actions on web pages until you approve them here, in the extension. In agent mode, which you turn on, it holds payments, sending messages and deletions, and uploads to a new site or from a session that has seen private data. With agent mode off it still holds account security changes, granting apps access and executable downloads. It can only enforce what a browser extension is allowed to enforce. This page lists what it cannot stop, so you know when not to rely on it.

Known bypasses of the action gate

  • Script calling form.submit(). A page script, or an agent that runs JavaScript in the page (for example a "run JavaScript" tool or CDP Runtime.evaluate), can submit a form without the submit event LaunchSafe listens for. The form is sent without approval.
  • Script sending requests directly. fetch, XMLHttpRequest and navigator.sendBeacon called from page script send data without any click or form. LaunchSafe does not see them as actions. Only requests to about 50 well-known request-catcher, paste and tunnel sites are always blocked.
  • Sites that ignore replayed actions. After you approve, LaunchSafe carries out the action itself. A few sites ignore actions that do not come from real input; there, approve and then do it yourself with agent mode off.
  • Sends with no labelled control. Apps that send through their own code, with no recognisable Send button or form, on sites without a LaunchSafe adapter, are not held. The leak guard still checks data typed into forms.
  • Downloads: the first request is already sent. An executable download is cancelled before the file is saved, but the browser has already asked the website for the file. Files you already have on disk are out of reach.
  • Downloads under remote automation. A remote automation tool that takes over the browser's download handling saves files without LaunchSafe seeing them.
  • Text in images. Instructions drawn inside images are not read.
  • Closed shadow roots and stylesheet text. Controls, forms and text inside a closed shadow root, and text a page's stylesheet generates, are not seen.
  • Hidden text read first. In agent mode hidden instructions are removed from the page, but an agent that reads the page before the removal can still see them.
  • Data in addresses opened by script. A clicked link carrying private data is held; an address opened by script or typed into the address bar is checked only by the navigation rules.

Also out of reach

  • What an agent sends to its own vendor, and its connectors (for example a mail API).
  • The browser's own pages and UI (chrome:// pages, the address bar, built-in assistant panels).
  • Other extensions, including malicious ones, and malware on the computer.
  • A person approving without reading: the approval shows what will happen; it cannot make anyone read it.

Approvals never happen on a web page. If a page shows a "LaunchSafe approved" button or dialog, it is fake.
